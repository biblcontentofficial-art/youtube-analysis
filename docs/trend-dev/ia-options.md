## 안별 장단점

### 안 A · 브레이크아웃 탭 5개 (설계 기본값)

- 좋은 점: 다섯 화면이 모두 `breakout_videos` 한 출처라 규칙 설명이 한 곳에 모인다. 탭마다 자기 데이터만 읽어 느려지지 않는다. 허브는 거의 그대로다. 이미 만든 탭 줄(T1 `BreakoutTabs`)을 그대로 쓴다.
- 아쉬운 점: 새 기능이 브레이크아웃 안쪽 탭에 있어 허브에서 바로 보이지 않는다. 처음 온 사람은 '브레이크아웃' 링크를 눌러야 탭이 있는 줄 안다(허브 설명 문구로 보완, spec 1.4).

### 안 B · 허브 목록에 항목 추가

- 좋은 점: 허브에서 새 기능 이름이 바로 보이고 한 번에 들어간다. 브리핑이 사이트 트렌드 서치 첫 화면에 보인다.
- 아쉬운 점: 허브 목록이 8가지로 길어지고, 요금제 잠금 도구와 로그인만 필요한 도구가 섞인다. 같은 날짜·롱폼/쇼츠·제외 설명을 페이지마다 반복한다. 브리핑이 날짜 칩과 떨어져 '어느 날 요약인지'를 고를 수 없다. 허브는 지금 로그인 없이 보는 화면이라, 로그인 사용자용 브리핑을 넣으면 비로그인 때 비울지 안내할지 정해야 한다.

### 안 C · 브레이크아웃 한 페이지

- 좋은 점: 한 화면을 내려 보며 오늘 흐름을 다 본다. 브리핑 → 키워드 → 채널 → 영상 순서가 읽는 순서와 맞다.
- 아쉬운 점: 페이지 하나가 데이터 4~5개를 한꺼번에 읽어 첫 화면이 느려질 수 있다(성능 기준: 서울 리전 고정, 탭마다 자기 데이터만). 모바일에서 영상 표까지 길게 내려야 한다. 날짜 칩이 섹션마다 다른 기간과 섞여 뜻이 헷갈린다. 내 채널 카드(C8)·필터는 '전체 보기' 페이지로 가야 하므로 결국 하위 페이지 넷이 함께 필요하다.

## 시안에서 정한 것(설계 문서에 없던 부분)

- 안 B 의 새 페이지 주소는 `/trend-search/rising` · `/trend-search/rising-channels` · `/trend-search/growth` · `/trend-search/watch` 로 가정했다(기존 `/channels` 와 헷갈리지 않게).
- 안 B 허브 목록 머리는 '분석 도구 8가지'. 브레이크아웃(영상) 글자 링크와 설명은 지금 문장 그대로 뒀다.
- 안 C 의 성장 추적·관심 목록은 섹션이 없어 머리 아래 글자 링크로 들어가게 했다. 영상 섹션은 이 페이지의 본 목록이라 '전체 보기' 링크를 두지 않았다. 안 C 의 페이지 설명은 spec 1.4 의 허브 설명 문장을 썼다.
- 허브 화면(안 B)의 잠금 표시는 Free 계정 기준으로 그렸다.
- 내 채널 카드(C8)는 AI 판정 상태(method=ai) 하나로 그렸다. 그래서 카드 아래 안내는 외부 AI 안내 하나다. AI 를 못 쓸 때의 겹치는 주제 상태(참고값 안내가 붙는 쪽)는 시안에 넣지 않았다.
- 열 폭·라벨 폭(브리핑 라벨 칸, 대표 영상 열 등)은 시안 값이며 실제 구현에서 spec 값으로 맞춘다. 미리보기 폴더는 Tailwind 가 따로 읽지 않아, 이미 쓰이는 폭 클래스로 바꿔 그렸기 때문이다.
- 390 폭 영상 목록의 메타 줄은 줄이 넘어가면 구분점(·)이 다음 줄 맨 앞에 온다. 정보 구조와 상관없는 부분이라 시안은 그대로 두고, 실제 구현(T3 이후)에서 줄바꿈 방식을 정한다.
