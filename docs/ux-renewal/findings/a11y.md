# a11y 영역 감사 (횡단: 접근성과 상호작용 상태)

- 범위: `src` 전체 grep 조사(focus·outline·aria·role·alt·label·button type·onClick 비시맨틱 요소·작은 글자·터치 영역·모달·tabIndex·motion) + 아무 보고서도 접근성 관점으로 보지 않은 화면(/search 결과, 커뮤니티) 정밀 확인
- 명암비: 설치된 Tailwind v4.1.18(`node_modules/tailwindcss/theme.css`)의 oklch 값을 sRGB 8비트로 변환해 WCAG 상대휘도로 직접 계산(스크립트: `scratchpad/ux/work/contrast.py`)
- 실측: 프로덕션 bibllab.com 을 Chrome 으로 열어 키보드 Tab 후 `getComputedStyle`·`elementFromPoint` 확인(읽기 전용, 검색 실행 없음)
- 본 스크린샷: `shots/before/search-desktop-01.png`, `search-mobile-01.png`, `studio-class-consulting-mobile-04.png`, `-09.png`, `shots/before-auth/community-feed-top.jpg`
- 다른 영역과의 경계: 상담 폼(studio-11), 결제 입력(pricing), 채널·스레드 표(channels-14), 모바일 네비 터치 높이(mobile-01), 카카오 버튼 겹침(mobile-03), 모바일 정렬 부재(mobile-04), 컨설팅 상세 이미지(class-04), 네비 현재 위치(shell-04)는 해당 보고서가 다룬다. 여기서는 전역 근본 원인과 미검토 화면에 집중한다.

## 총평

접근성의 기본기(`lang="ko"`, 확대 허용, 이미지 alt 지정, 링크·버튼의 브라우저 기본 포커스 링)는 살아 있지만, 그 위의 상호작용은 거의 마우스 기준이다. ARIA 는 커뮤니티 신규 코드에만 있고(aria-label 15, aria-current 1, role="status" 1, aria-expanded·aria-live·aria-modal·aria-invalid 0), 서비스 본체인 검색 결과는 영상 상세 열기·정렬·선택이 div/h3 onClick 이라 키보드로 쓸 수 없다. 가장 넓게 퍼진 문제는 명암비다. 검정 바탕에서 본문 기준(4.5:1)을 넘는 회색은 neutral-400 부터인데, 그보다 어두운 회색 글자가 601회(그중 12px 이하 336회) 쓰였다. "포커스가 보이지 않는다"는 기존 판단은 링크·버튼에 대해서는 사실과 다르다(Chrome 실측에서 기본 링이 보임). 실제 결함은 설계되지 않은 기본 링, 입력창의 1px 테두리 변화, 고대비 모드에서의 소실이다. 768~1,066px 폭에서는 상단 메뉴가 로고를 덮는 눈에 띄는 오류가 있다.

## 유지할 점

1. `<html lang="ko">`(`src/app/layout.tsx:276`), 확대를 막지 않는 viewport(`maximum-scale`·`user-scalable` 0건).
2. 이미지 alt 지정: `<img>` 45개 + `next/image` 10개 모두 alt 가 있고, 장식 이미지는 `alt=""` (예: `VideoCard.tsx:168`).
3. 버튼·링크에 `outline-none` 을 걸지 않아 브라우저 기본 포커스 링이 살아 있다. 전역 규칙을 넣을 때도 버튼에 outline-none 을 추가하지 말 것.
4. 커뮤니티 신규 코드의 패턴: `CommunityTabs.tsx:55`(aria-current + 밑줄 + 굵기, 색 단독 아님), `PostForm.tsx:319-370`(label htmlFor), `LikeButton.tsx:117-143`(aria-pressed + role="status"), `CategoryChips.tsx:35`(nav aria-label), `community/page.tsx:143-153`(JS 없이 동작하는 GET 검색 폼 + aria-label). 다른 화면의 기준으로 삼는다.
5. `KakaoChatButton.tsx:7-25`: aria-label, 56px 터치 영역, SVG aria-hidden.
6. `VideoModal.tsx:116-132`: ESC 닫기 + body 스크롤 잠금·복원. 공용 셸로 옮길 때 그대로 살린다.
7. `BlockEditor.tsx:369`: 블록 컨트롤이 hover 와 focus-within 둘 다로 드러난다. 커뮤니티 글쓰기 버튼은 모두 `type="button"` 이라 폼 안 오작동이 없다.

### a11y-02 · P1 · accessibility · 공수 M (전역 S + 파일별 M)
**회색 보조 글자 601회가 본문 명암비 4.5:1 미달, 모든 페이지 푸터는 1.9~2.5:1**

- 근거
  - 계산값: 위 표. neutral-500 은 검정 위 4.43:1 로 아슬아슬하게 미달, 카드(neutral-900) 위 3.78:1. neutral-600 2.29~2.69:1, neutral-700 1.73~2.03:1.
  - 사용량(hover·placeholder 제외, `grep -rhoE "(^|[^:a-z-])text-<색>\b" src`): text-neutral-500 133회/32파일, -600 29/13, -700 5/5, text-gray-500 248/46, -600 118/37, -700 9/6, text-slate-500 46, -600 12, -700 1 = 601회. 같은 줄에 text-xs 이하가 있는 경우 336회. `placeholder-neutral-600` 15회(입력창 예시 글자 2.29:1).
  - 모든 페이지 푸터: `src/app/layout.tsx:415, 419`(text-xs neutral-600 on bg-neutral-950 = 2.53:1), `:436`(neutral-700 = 1.91:1), 링크 `:429-432, 439, 441`(neutral-500 = 4.18:1). `shots/before/search-desktop-01.png` 하단의 사업자 정보·저작권 줄이 거의 읽히지 않는다.
  - 주요 동선의 읽어야 하는 문장: 홈 로그인 모달 안내 `src/app/page.tsx:109`, "인기 키워드:" `:182`, 로그인 `src/app/sign-in/_components/SignInForm.tsx:224, 285`(neutral-600), `:298`(neutral-700), 회원 전용 안내 `src/app/community/_components/CommunityGate.tsx:78`, 요금제 하단 안내 `src/app/pricing/page.tsx:46`, 상담 폼 `src/app/studio/consulting/page.tsx:221, 240, 361, 465`.
- 문제: 사업자 정보·약관 고지·가입 안내·폼 안내처럼 읽어야 하는 문장이 장식 수준의 회색으로 쓰였다. 저시력 사용자와 밝은 실외의 휴대폰 사용자는 읽지 못한다. 구 테마의 gray-600(2.4~2.8:1)을 테마 변환 때 같은 단계(neutral-600)로 옮기면 문제가 그대로 남는다.
- 제안
  1. 전역 1회: `globals.css` 에 `@theme { --color-neutral-500: oklch(60% 0 0); }`. 클래스를 하나도 바꾸지 않고 neutral-500 133곳이 검정 5.32:1, neutral-950 5.01:1, neutral-900 카드 4.54:1 로 올라간다. 무채색 유지. neutral-500 을 쓰는 테두리 hover 도 한 단계 밝아지는 부작용은 미미하다(디자인 시스템 영역과 확인).
  2. 파일별: 읽어야 하는 문장의 `text-neutral-600·700` 34곳을 `text-neutral-400`(1 적용 후에는 neutral-500 도 가능)으로, `placeholder-neutral-600` 15곳을 `placeholder-neutral-500` 으로. 장식 숫자(`page.tsx:286`, `studio/page.tsx:624`, `not-found.tsx:7`)는 색을 두고 `aria-hidden="true"`.
  3. 규칙(테마 변환 매핑에 반영): 정보 글자는 neutral-400 이상, neutral-500 은 보조 문구까지, neutral-600·700 은 글자에 쓰지 않는다(구분선·비활성·장식만). 매핑은 gray-500→neutral-400, gray-600·700→neutral-500.

### a11y-03 · P1 · accessibility · 공수 M
**검색 결과의 영상 상세 열기·선택·정렬을 키보드와 스크린리더로 쓸 수 없음**

- 근거
  - 영상 상세 열기: `src/app/search/_components/VideoCard.tsx:144`(썸네일 `<div onClick>`), `:155`(제목 `<h3 onClick>`), 모바일 `:221`, `:240`. role·tabIndex·onKeyDown 없음(src 전체 tabIndex 0건).
  - 선택: `VideoCard.tsx:131, 217`, 전체 선택 `SearchResultList.tsx:382-387` 이 `w-3.5 h-3.5`(14px) 체크박스이고 label·aria-label 이 없다. 스크린리더는 "체크박스, 선택 안 됨"만 읽는다. 감싸는 div 에 패딩이 없어 터치 영역도 14px.
  - 정렬: `SearchResultList.tsx:392-410` 이 `<div onClick>`, `aria-sort` 없음. 비활성 표시 `↕` 는 text-gray-700 10px(`:276`, 검정 위 2.04:1).
  - 표 구조: 헤더·행이 모두 div 그리드(`:377-436`)라 "조회수"·"구독자" 머리글과 값이 연결되지 않는다.
  - 검색 기록: `src/app/_components/SearchBar.tsx:324`(펼치기 `<div onClick>`), `:354`(기록 항목 `<div onClick>`). 삭제 버튼 `:360-367` 은 이름 없는 14px 아이콘(neutral-600 on neutral-800 = 1.94:1).
- 문제: 이 화면이 서비스의 본체인데 키보드 사용자는 영상 상세(설명·댓글·채널 정보)를 열 수 없고 정렬도 못 한다. 스크린리더 사용자는 제목이 눌리는 요소인지, 체크박스가 어느 영상의 것인지 알 수 없다. 14px 체크박스는 모바일에서 수집할 영상을 고르는 유일한 수단이다.
- 제안 (UI 계층만. `executeSearch`·`saveToHistory`·`navigateFromHistory`·정렬 함수는 그대로 호출)
  1. 제목을 `<h3><button type="button" onClick={onClick} className="text-left …">{title}</button></h3>` 로. 썸네일은 같은 동작의 두 번째 Tab 정지점이 되지 않게 마우스 전용으로 두고 `alt=""`(a11y-05).
  2. 체크박스에 `aria-label={`${video.title} 선택`}`, 전체 선택에 `aria-label="전체 선택"`. `<label className="p-3">` 로 감싸 히트 영역 40px 이상, 시각 크기 16~18px.
  3. 정렬 머리글은 `<button type="button">` + 머리글 칸에 `aria-sort`. 화살표는 SVG 하나로 통일(channels-14 와 같은 패턴).
  4. 그리드에 `role="table"`·`row`·`columnheader`·`cell` 을 주거나, 최소한 행의 값마다 `sr-only` 라벨("조회수", "구독자", "게시일").
  5. 검색 기록 펼치기·항목은 `<button type="button">`(펼치기에 `aria-expanded`), 삭제 버튼에 `aria-label={`${item.term} 기록 삭제`}`.
- 관련: mobile-04(모바일에서는 정렬·전체 선택 자체가 없음).
