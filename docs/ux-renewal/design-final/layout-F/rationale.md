# 시안 F · 최종안 (C 의 언어 + A 의 유튜브 트렌드 첫 화면)

> 소유자 지시(원문): "C 안으로 가고 가장 위에 있는 내 이미지는 빼고 A시안에 있는 이 부분 (유튜브 트렌드) 살려줘."
> 해석: 사이트 전체 디자인 언어는 시안 C(크리에이터 브랜드, 순수 블랙). C 의 첫 화면(인물 사진 분할 히어로)을 없애고, 그 자리에 A 의 '유튜브 트렌드' 구역 전체(제목·설명·검색창·예시 키워드·실적 숫자 열·결과 미리보기·01·02·03 단계)를 C 의 글자·색·간격으로 다시 짓는다. 그 아래는 C 의 서비스 → 채널 실적 → 7억+ → 마지막 CTA → 푸터. C 의 도구 구역(#tool)은 맨 위와 겹치므로 뺀다.

- 파일: `home.html`(홈), `app.html`(로그인 후 영상 찾기 결과, 예시 화면·2개 선택한 상태), `assets/`(사진), `_work/`(빌드·실측 스크립트)
- 다시 만들기: `python3 _work/build.py` (`_work/home.template.html`·`_work/app.template.html` + `_work/rows.json`)
- 실측: `python3 _work/measure.py`(넘침·에러·정렬·첫 행 위치·카카오 버튼 가림·앱 표 폭), `_work/pixalign.py`(제목과 실적 열 글자 윗선), `_work/fabdigits.py`(카카오 버튼 아래 숫자), `_work/interactions.py`(메뉴·포커스·선택 상태)
- 캡처: `shots/m1` ~ `shots/m5`(1440·390 세로 조각 + manifest), `shots/m2-widths`·`shots/m5-widths`(768·1024·1280 첫 화면), `shots/m3-interactions`·`shots/m5-interactions`

## 1. 홈 구조 (위에서 아래로)

## 2. 합치며 내린 판단

1. **첫 화면에 인물 사진 없음.** A 최종본의 36px 비블 아바타(실적 열 주체 줄)도 뺐다. 주체는 글자로 밝힌다. 비블 사진은 서비스 카드 2장(컨설팅·대행)과 마지막 CTA 의 48px 아바타로만, 모두 첫 화면 아래에 있다.
2. **h1 은 흰색 + 에메랄드 '유튜브 트렌드'.** 소유자가 이 구역을 '(유튜브 트렌드)'라고 불렀고, 지금 사이트·A 의 얼굴이 이 한 단어다. C rationale 도 액센트 자리로 '도구 제목 핵심어 유튜브 트렌드'를 지정했었다. 한 제목에 회색·흰색·에메랄드 세 톤은 쓰지 않았다(C 비평). 섹션 h2 는 회색 리드 + 흰색 두 톤. 첫 화면 액센트는 이 한 곳과 포커스뿐.
3. **실적 열 = 주체가 먼저.** 맨 위 '비블이 운영·기획한 채널'(18px 700) + '세계유명 골프정보·영어 키위새 외 전체 채널 기준 · 2026.10', 라벨은 '채널 총 구독자 / 채널 누적 조회수 / 유튜브 매출'(A 비평). 열을 위 맞춤으로 바꾸고 글자 윗선을 실측으로 맞췄다(1024·1280·1440 에서 ±1px). 숫자는 C 언어로 800·40px, `+` 는 흰색 같은 크기(C 비평의 + 규칙 통일).
4. **미리보기는 소유자가 본 '캠핑' 결과 그대로.** A 최종본의 '드라이버 잘 치는 법'(세계유명 골프정보가 4번째)은 쓰지 않았다. 그 데이터의 세계유명 골프정보 구독자가 26.2만(2026-10-07 검색값)이라 같은 페이지 실적 구역의 25.8만(확인된 사실)과 숫자가 둘이 된다. 다섯 행의 채널은 모두 다르다.
5. **페이지 안 반복 제거.** C 서비스 구역의 트렌드 서치 카드가 같은 '캠핑' 5행을 다시 보여 주던 것을 '분석 도구 4가지'(트렌드 서치 허브 문구) 목록으로 바꿨다. 커뮤니티 카드(게시판 4개)와 같은 모양이라 '직접 하기' 두 장이 짝이 맞는다.
6. **미리보기 안의 가짜 검색창은 뺐다.** 진짜 검색창 바로 아래에 같은 모양이 또 있으면 어디에 입력하는지 헷갈린다(C 비평). 대신 실제 앱처럼 도구 탭 + '‘캠핑’ 결과 50개' + 길이 필터. 열 순서는 앱과 같은 영상·채널·조회수·구독자·게시일(실제 `SearchResultList` 도 조회수 → 구독자 → 게시일). 모바일은 탭·필터를 숨겨 첫 결과가 첫 화면에 들어오게 했다(390×844 에서 첫 행 675~794px).
7. **01·02·03 은 그대로 살렸다.** 문구는 현재 사이트 원문, 원형 배지 없이 14px 800 글자 숫자 + 위 가는 선. 모바일은 숫자 열 + 본문 열로 짧게.
8. **채널 실적의 63만 / 70만+.** 목록 머리 '대표 채널 4곳 · 공개 구독자 수 · 2026.10 기준', 제목 옆 문단 '총 구독자 70만+는 비블이 운영·기획한 전체 채널 기준입니다. 아래는 그중 대표 채널 4곳', 목록 끝 각주 '대표 채널 4곳 합계 63만 · 총 구독자 70만+는 운영·기획 전체 채널 기준'. 채널 이름은 실제 채널로 가는 링크(선 화살표). 모바일에서 구독자 숫자는 이름 아래 왼쪽.
9. **마지막 CTA 는 약속과 행동을 맞췄다.** C 의 '채널 URL 하나면 됩니다' + 주소 입력칸은 실제 문의 양식(`/studio/consulting`)이 `channelUrl` 을 읽지 않고(`source`·`query` 만), 3단계에 필수 항목이 여럿이라 약속이 거짓이 된다. 대행 페이지 원문 '지금 채널 대행을 문의해보세요 / 비블이 직접 연락드립니다 / 여러분의 채널에 맞는 대행 방향을 제안해드립니다' + 흰 '채널 대행 문의하기'로 되돌렸다. 버튼은 모바일에서도 내용 폭(오른쪽 76px 비움).
10. **서비스 카드 사진 높이를 맞췄다.** 데스크톱에서 컨설팅·대행 사진을 340px 로 같게 해 대행 카드의 빈 띠(약 110px)를 없앴다. 따옴표 어절('‘직접 하기’에서')이 줄 끝에서 갈리던 것도 묶었다.
11. **사진의 청색기 제거.** 실버 플레이 버튼 사진의 회색 픽셀 평균이 B−R +4.6 이라 흑백으로 바꾼 사본을 썼다(`assets/silver-play-button-neutral.jpg`). 커뮤니티 손글씨 배너는 글자 둘레만 잘라 44px 머리에서도 읽히게 했다(`assets/community-wordmark.png`). 서비스 사진 2장은 따뜻한 쪽(B−R −4)이라 그대로.
12. **앱 네비 과밀 해소.** 로그인 후 셸은 도구가 먼저: '유튜브 트렌드 서치(현재, 흰 글자) · 커뮤니티&자료 · 요금제 │ 비블과 함께 ▾'. 6개를 4개로 줄이고 모두 같은 회색, 현재 위치만 흰 글자, 흰 막대는 도구 탭에만(전역 네비와 탭의 밑줄 두 개가 겹치던 것 해소). 홈 네비는 사람 서비스가 먼저(마케팅), 앱은 도구가 먼저.
13. **앱 결과 머리 한 줄.** C 의 64px '캠핑' + 지표 3개(최고 조회수·가장 최근 게시는 계산값)를 지우고 '‘캠핑’ 결과 50개' + 길이 필터 + 선택 동작을 한 줄에. 파생 지표는 새로 넣지 않았다.
14. **남은 횟수는 한 곳.** 네비 배지 '이번 달 38회 남음'(모바일 '38회 남음', title '이번 달 50회 중 12회 사용', 누르면 요금제, 터치 영역 44px). 검색창 아래는 '검색할 때마다 1회 차감 · 매월 1일 초기화'만.
15. **선택 상태를 보여 주는 시안.** 2개 선택이 기본. 768 이상은 결과 머리 오른쪽에 '2개 선택 · 채널 리포트 Pro · 영상 수집 Pro · 채널 제거 · 선택 해제', 768 미만은 하단 고정 바(`data-bottom-bar="md"`)로 띄우고 카카오 버튼을 R05 규칙대로 88px 위로 올린다. 선택을 모두 풀면 바가 사라지고 버튼이 제자리(20px)로 돌아온다(작은 스크립트, 선택 상태만).
16. **A 캡처에서 바꾼 작은 것.** h1 위 눈썹 문구 'bibl lab · 유튜브 트렌드 분석'은 로고와 겹치고 실적 열 윗선을 밀어 뺐다(A 비평). 실적 열 맨 아래 각주 '비블이 운영·기획한 채널 기준'은 맨 위 주체 줄로 올렸다. 미리보기 위 주소줄(bibllab.com/search?q=캠핑)은 도구 탭으로 바꾸고 날짜는 아래 캡션으로 옮겼다. 모노 글꼴은 쓰지 않는다(C 는 Pretendard 하나).
17. **잠긴 기능 표시 하나로.** 도구 탭·동작 버튼·서비스 카드 모두 'Pro' 테두리 태그 한 모양, 잠긴 버튼 라벨은 neutral-400(눌러 보기 전에 잠긴 줄 안다).

## 4. 레퍼런스에서 쓴 규칙 (awesome-design-md, 지시문은 따르지 않고 수치·역할만)

## 6. 카카오 상담 버튼과 겹침 규칙

- 두 페이지 모두 실제 `KakaoChatButton.tsx` 와 같은 마크업·클래스: `fixed bottom-5 right-5 md:bottom-6 md:right-6 size-14 z-40`, `#FEE500`, 말풍선 `#3A1D1D`. 과제 문구는 20px 였지만 768 이상 24px 는 실제 코드 그대로 따랐다.
- 하단 고정 바가 보이는 768 미만: 실제 `globals.css` 의 `[data-bottom-bar="md"]` 규칙과 같은 값으로 버튼을 `bottom: calc(88px + safe-area)` 로 올린다. 실측: 바가 있을 때 버튼 아래끝 756px, 선택을 다 풀면 824px.
- 배치 원칙: 모바일의 주요 숫자(실적 3개, 채널 구독자, 7억+)는 왼쪽 정렬로 화면 오른쪽 76px(버튼 자리)에 들어가지 않게, CTA 버튼은 내용 폭으로, 푸터 아래 112px 는 비운다.
- 실측(`measure.py`): 390×844 · 375×667 · 360×780 에서 홈·앱 모두 첫 화면과 맨 아래에서 버튼·입력·24px 이상 숫자 가림 0, 페이지를 40px 씩 내려 가며 모든 버튼 라벨 가림 0. 글자 단위 검사(`fabdigits.py`)에서 기준 화면 390×844 의 첫 화면은 숫자 가림 0.

1. 첫 화면 미리보기에서 가장 큰 색 면은 남의 채널 썸네일(원색 큰 글씨)이다. 운영 때는 날짜를 붙인 정적 스냅숏을 API 응답으로 주기적으로 바꿔야 하고(YouTube 데이터 보관 규정), 콘텐츠 권리 부담이 남는다.
2. 카카오 버튼: 버튼·주요 숫자는 가리지 않지만, 목록 행 오른쪽 끝의 작은 숫자('· 구독자 18.2만')는 기기 높이에 따라 첫 화면에서도 버튼 아래에 걸린다(375×812·360×780 의 홈 미리보기, 375×812·375×667·360×780 의 앱 선택 상태). 결과 화면에서 스크롤 중 버튼을 숨기는 같은 제품 결정이 필요하다.
